# 06. 거버넌스·위험 관리

## 1. 대표 위험

| 위험 | 잘못된 사용 | 통제 방법 |
|---|---|---|
| 확률 오해 | 전형성 값을 성공확률로 표시 | UI 명칭·도움말·스키마 분리 |
| 저확률 숭배 | 희귀하면 좋은 아이디어로 자동 채택 | 품질·제약·사실성 게이트 |
| 의미 중복 | 표현만 다른 후보를 다양하다고 판단 | 임베딩·메커니즘 요약 |
| 환각 | 기술·법률·시장 사실을 창작 | 근거 필드·외부 검증 |
| 대표성 오해 | 가상 사용자를 실제 인구로 간주 | 실제 데이터 교정·가설 표시 |
| 민감정보 | 발명·고객자료를 외부 API에 전송 | 로컬/온프레미스·로그 정책 |
| 저작권·스타일 | 특정 작가·작품 복제 | 추상적 원칙·유사도 검사 |
| 위험 시나리오 악용 | 안전·보안 후보가 공격 지침으로 전환 | 목적 제한·검수·세부도 제어 |
| 비용 폭증 | Multi-Batch 무제한 실행 | 예산·후보 목표·조기 종료 |
| 자동 의사결정 | 사람이 검토하지 않고 채택 | human-in-the-loop 승인 |

## 2. 전형성 표시 규칙

권장:

- 모델 추정 전형성 0.07
- Tail 탐색 후보
- 절대 확률이 아닌 휴리스틱

금지:

- 성공확률 7%
- 특허등록확률 7%
- 시장점유 가능성 7%
- 실제 발생확률 7%

## 3. 품질과 다양성 분리

최소 대시보드는 다음 지표를 분리한다.

- semantic_diversity
- duplicate_rate
- constraint_pass_rate
- factual_support_rate
- feasibility_score
- quality_score
- safety_risk
- cost
- latency

하나의 종합점수만 표시하면 낮은 전형성과 높은 품질이 혼동된다.

## 4. 특허·R&D

- 신규성·진보성·FTO를 단정하지 않는다.
- 검색 전 후보는 `발명 가설`로 표시한다.
- 검색식과 충돌 가능성을 함께 출력한다.
- 공개 전 비밀유지와 출원전 공개 위험을 검토한다.
- 최종 문서는 변리사·법무·R&D 책임자가 승인한다.

## 5. 사용자·사회 시뮬레이션

- 페르소나 후보는 실제 인구비율이 아니다.
- 민감 속성의 고정관념을 검수한다.
- 실제 설문·행동 로그와 비교한다.
- 정책 결정이 아니라 시나리오 탐색에 사용한다.

## 6. 안전·보안 분야

- 예방·훈련·테스트 목적을 명확히 한다.
- 실제 위해 실행에 필요한 세부 단계는 필요 최소한으로 제한한다.
- 현장 표준과 제조사 매뉴얼을 우선한다.
- 생성 시나리오는 전문가가 위험도와 사실성을 검수한다.

## 7. 공개 저장소 체크

- API 키 없음
- 고객·회사명 제거
- 논문 PDF 미포함
- 제3자 코드·이미지 라이선스 확인
- 특정 작가 모사 프롬프트 제거 또는 일반화
- 생성 결과의 법적·통계적 한계 명시
