# 14. 확장 적용·플랫폼·사업구상 종합 보고서

## 1. 경영 판단 요약

Idea Diversity Engine의 핵심 가치는 소설을 자동 작성하는 데 있지 않다. **LLM이 가장 익숙한 답으로 수렴하는 현상을 줄이고, 서로 다른 작동 원리·관점·전략을 가진 후보 포트폴리오를 만드는 것**이 본질이다.

따라서 제품 포지셔닝은 다음처럼 잡는 것이 적절하다.

> 범용 아이디어 생성기 → **도메인별 탐색·검증·문서화 엔진**

무료 공개 코어는 프롬프트·스킬·스키마·검증기를 제공한다. 유료 가치는 도메인 입력 폼, 의미 중복 제거, 품질 루브릭, 업무 문서 변환, 팀 승인, 보안과 통합에서 만든다.

## 2. 어떤 문제에서 가치가 큰가

적합한 문제는 다음 네 조건을 가진다.

1. 정답이 하나가 아니다.
2. 비슷한 답을 여러 개 받으면 가치가 급격히 떨어진다.
3. 후보를 비교·병합·선택할 수 있다.
4. 별도의 품질·사실·위험 검증이 가능하다.

반대로 단일 사실 질의, 계산, 법적 결론, 대표성 있는 여론 추정에는 단독 사용하지 않는다.

## 3. 활용 분야 포트폴리오

| 우선순위 | 분야 | 대표 출력 | 구매 이유 | 권장 상품 형태 |
|---:|---|---|---|---|
| 1 | 산업안전·체험훈련 | 사고 전조, 오조작, 센서 판정, 피드백, 난이도 변형 | 반복 시나리오와 현장별 커스터마이징 비용 감소 | Safety Scenario Studio |
| 2 | R&D·IP | 발명 후보, 회피설계, 실시예, 검색식, 검증실험 | 발명 인터뷰와 선행기술 탐색 범위 확대 | IP Harvest Workbench |
| 3 | 게임·라이브옵스 | 몬스터, 스킬, 퀘스트, 이벤트, 보스, 다회차 엔딩 | 콘텐츠 반복과 전략 단조 감소 | Game LiveOps Forge |
| 4 | 3D·제품 콘셉트 | 실루엣, 부품, 재질, 제작공정, LOD 브리프 | 첫 콘셉트 고착과 모델링 재작업 감소 | 3D Concept Variation Lab |

| 6 | AI 펫·NPC | 감정·행동·대사 후보, 기억 저장, 성장 신호 | 반복 반응을 줄이고 캐릭터 생동감 향상 | Behavior Portfolio Studio |

| 8 | 연구·교육 | 가설, 실험, 반례, 문제 변형, 역할극 | 탐색 범위와 학습 데이터 커버리지 확대 | Research/Education Pack |
| 9 | 소설·웹툰·영상 | 제목, 세계관, 인물, 플롯, 엔딩, 이미지 프롬프트 | 무료 유입과 대중적 이해가 쉬움 | Creator Workspace |

소설·콘텐츠 제품은 사용자가 개념을 빠르게 이해하는 유입 채널로 적합하다. 반복 매출과 방어력은 안전·IP·게임·QA처럼 **도메인 스키마와 검수 문서가 필요한 수직 제품**에서 더 높다.

## 4. 공통 제품 구조

```text
사용자 브리프
  ↓
문제·제약·기대효과 정규화
  ↓
전형적 기준안 파악
  ↓
해결 공간 4~8개 층화
  ↓
Verbalized Sampling 후보 생성
  ↓
현재·과거 후보 의미 중복 제거
  ↓
제약·품질·사실·위험 게이트
  ↓
서로 다른 메커니즘의 포트폴리오 선택
  ↓
도메인 문서로 변환
```

공통 코어는 모델 제공사에 종속시키지 않는다. OpenAI, Anthropic, Gemini, 로컬 LLM은 어댑터로 분리한다.

- Blender/Unity/Godot/Unreal 플러그인: 3D 브리프·퀘스트·NPC·레벨 기믹
- Chrome 확장: 웹 문서·Notion·CMS에서 선택 영역을 후보 포트폴리오로 확장

## 6. 사업모델

### 오픈코어

무료 공개:

- 기본 프롬프트와 스킬
- JSON Schema
- CLI 프롬프트 빌더·검증기
- 샘플 브리프와 평가 방법

유료 영역:

- 수직 도메인 팩
- 프로젝트 저장·의미 메모리
- 팀 평가·투표·승인·감사로그
- API/MCP 사용량
- 업무 문서 exporter
- 조직별 보안·온프레미스

### 현실적인 매출 순서

1. **워크숍·문서 제작 서비스**로 실제 문제와 지불의사 검증
2. 반복되는 입력·출력을 수직 팩으로 제품화
3. 팀 워크스페이스와 API/MCP 판매
4. 온프레미스·화이트라벨·연간 유지보수 확대

### 방어력

1. 도메인 사례와 평가 데이터
2. 조직별 과거 후보 의미 메모리
3. 실제 업무 문서 exporter
4. 전문가 검수 네트워크
5. 권한·감사·보안·업무시스템 통합
6. 프롬프트 문구

## 7. 우선 개발 상품

### 7.1 Safety Scenario Studio

입력: 작업, 대상, 장비, 센서, 환경, 필수 행동, 금지 연출, 평가 방식.

출력: 사고 전조, 오조작, 분기, 센서 판정, 피드백, 난이도 변형, 다국어 나레이션, 제작 체크리스트.

차별점: 일반 스토리 생성이 아니라 **체험 장치·UI·판정·교육효과를 하나의 제작 명세로 연결**한다.

### 7.2 IP Harvest & Design-Around

입력: 기술 문제, 현재 구조, 필수 효과, 자산, 제약, 회피 대상.

출력: 해결 공간 지도, 발명 후보, 기술 구성·연결·작동·효과, 검색 키워드, 실시예, 검증실험.

주의: 모델 전형성은 신규성·진보성·등록 가능성 확률이 아니다. 선행기술 검색과 전문가 검토가 필수다.

### 7.3 Game LiveOps Forge

입력: 장르, 핵심 루프, 현재 콘텐츠, 피로 지점, 경제·전투 제약, 업데이트 목표.

출력: 시즌 테마, 이벤트 루프, 몬스터·보스·스킬, 엔딩 조건, 운영 위험, 플레이테스트 질문.

차별점: 콘텐츠 아이디어와 수치 밸런스를 분리하고, 결과를 JSON 리소스와 작업 티켓으로 변환한다.

## 8. 비용·성능 운영 원칙

Verbalized Sampling은 단일 답변보다 후보·구조 출력이 늘기 때문에 비용과 지연이 증가한다. 실제 서비스에서는 다음 원칙을 사용한다.

- 정규화·층화는 저비용 모델
- 최종 후보·평가는 고성능 모델
- `k=5` 소규모 배치
- 목표 다양성 도달 시 조기 종료
- 중복 후보만 부분 재생성
- 임베딩 캐시와 로컬 모델 활용
- 모델·프롬프트·토큰·지연·채택률을 함께 기록

전형성 수치는 UI에서 “확률”로 단정하지 말고 **모델 추정 전형성**으로 표시한다.

## 11. 핵심 위험과 통제

- **낮은 전형성=좋은 아이디어 오류**: 품질·구현·위험 점수 분리
- **전형성 수치의 과신**: 휴리스틱으로 명확히 표시
- **특허·시장·사회 분포 오해**: 실제 데이터·전문가 검수 의무화
- **회사 기밀 유출**: 브라우저 API 키 저장 금지, 서버 비밀관리, 로그 최소화
- **아이디어 수만 늘어나는 문제**: 후보 수보다 의미 커버리지·채택률 중심 평가
- **프롬프트 복제**: 수직 스키마·데이터·통합·검수 네트워크에 투자

## 12. 최종 제안

공개 저장소는 범용 엔진으로 유지한다. 첫 체험판은 소설·게임·안전 예제를 함께 보여주어 개념을 이해시키고, 첫 유료 제품은 **Safety Scenario Studio**로 집중한다. 다음 확장은 IP Workbench, Game LiveOps Forge, 3D Concept Lab 순서가 적절하다.

이 구조는 한 번 만든 다양성 코어를 콘텐츠, 제품, 사업, R&D, 교육, 게임, 안전, 소프트웨어 테스트로 재사용하면서도, 각 산업에서는 도메인 문서와 검수 규칙으로 별도 수익을 만들 수 있다.
