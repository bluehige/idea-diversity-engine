# 02. IP 아이디어 생성기 제품요구사항서(PRD)

## 1. 제품 목표

사용자가 기술·콘텐츠·서비스 문제를 입력하면, LLM의 상투적 수렴을 줄인 아이디어 포트폴리오를 만들고 조사·기획·특허 준비 문서로 변환한다.

## 2. 핵심 사용자

- 사내 R&D·기술기획 담당자
- 특허 발명 발굴 담당자
- 게임·콘텐츠 기획자
- 제품·서비스 PM
- 연구 가설·합성데이터를 만드는 연구자

## 3. 핵심 사용자 스토리

### US-01 문제 브리프

사용자는 자유문장 또는 폼으로 문제, 대상, 제약, 기존 방식, 기대 효과를 입력한다.

승인 조건:

- 필수 필드 누락 시 구체적 보완 질문을 3개 이하로 제시한다.
- 사용자 원문과 정규화된 브리프를 모두 보존한다.

### US-02 다양성 모드 선택

사용자는 Standard, Balanced, Tail, Stratified, Multi-Batch를 선택한다.

승인 조건:

- 모드별 `k`, `tau`, 배치 수, 온도를 고급 설정에서 조정할 수 있다.
- 기본값은 `k=5`, `tau=0.10`, `temperature=0.8~1.0` 범위다.

### US-03 후보 비교

사용자는 후보를 Head/Mid/Tail, 의미 층, 점수, 위험별로 비교한다.

승인 조건:

- 모델 추정 전형성의 의미와 한계를 항상 표시한다.
- 후보 점수의 근거 항목을 펼쳐 볼 수 있다.

### US-04 중복 제거

시스템은 현재 배치와 과거 배치의 의미 중복을 감지한다.

승인 조건:

- 중복 후보는 자동 삭제하지 않고 `중복`, `변형`, `유사하지만 핵심 차이 있음`으로 구분한다.
- 사용자가 병합·보존·재생성할 수 있다.

### US-05 IP 문서 변환

사용자는 선택 후보를 IP 검토 문서로 변환한다.

승인 조건:

- 기술적 문제, 수단, 작용, 효과가 분리된다.
- 검색 키워드와 예상 IPC/CPC 탐색 방향을 제공하되 자동 확정하지 않는다.
- 신규성·진보성을 단정하지 않는다.

## 4. 기능 요구사항

### FR-01 브리프 정규화

입력 필드:

- domain
- problem
- target_user
- current_solution
- pain_points
- hard_constraints
- excluded_approaches
- available_assets
- desired_effect
- jurisdiction(optional)

### FR-02 탐색층 생성

시스템은 4~8개 탐색층을 생성한다. 각 층은 상호 배타적일 필요는 없으나, 왜 별도 탐색 가치가 있는지 한 줄로 설명한다.

### FR-03 구조화 VS 생성

모델 응답은 `vs_candidate.schema.json`을 만족해야 한다.

### FR-04 모델 추정 전형성

- 0.0~1.0 숫자
- 전체 가능한 응답 분포 대비 추정치
- 후보 합계 1 강제 금지
- 실제 확률이 아니라는 경고 포함

### FR-05 품질 게이트

각 후보를 다음 기준으로 평가한다.

- relevance
- constraint_fit
- clarity
- feasibility
- technical_effect
- novelty_signal
- prior_art_risk
- safety_risk

### FR-06 의미 메모리

저장 항목:

- candidate_id
- canonical_summary
- embedding
- key_mechanisms
- stratum
- source_batch
- accepted/rejected/merged

### FR-07 수리 프롬프트

JSON 파싱 실패, 필드 누락, 확률 범위 오류, 후보 중복 시 전체 재호출보다 최소 수정 호출을 우선한다.

### FR-08 내보내기

- Markdown
- JSON
- CSV 후보표
- ZIP 프로젝트
- 선택 후보별 IP 검토 카드

## 5. 비기능 요구사항

### NFR-01 보안

- 공개 배포에서 클라이언트 API 키 저장 금지
- 민감 브리프 로그 비활성화 옵션
- 저장 데이터 암호화 또는 로컬 전용 모드

### NFR-02 추적성

모든 생성에 다음을 기록한다.

- model
- model_version
- prompt_version
- mode
- k
- tau
- temperature
- seed 또는 request_id
- timestamp

### NFR-03 비용

- 기본 한 호출 `k=5`
- 동일 브리프 결과 캐시
- 품질 통과 후보가 목표 수에 도달하면 조기 종료
- Multi-Batch는 사용자 승인 또는 예산 한도 필요

### NFR-04 접근성

- 색만으로 Head/Mid/Tail을 구분하지 않는다.
- 배지 텍스트와 수치를 함께 표시한다.
- 모바일에서 후보 비교는 1열 카드와 고정 필터를 사용한다.

## 6. 화면 구성

### S00 프로젝트 목록

프로젝트명, 도메인, 후보 수, 마지막 수정일, 상태.

### S01 브리프 작성

왼쪽 입력, 오른쪽 정규화 미리보기.

### S02 탐색 설정

모드, 다양성 다이얼, 층, 금지 패턴, 예산.

### S03 생성 결과

- 상단: 커버리지 맵
- 중앙: 후보 카드
- 우측: 필터와 의미 중복 경고

### S04 후보 비교

최대 4개를 열 기준으로 비교.

### S05 IP 문서화

기술 구성, 효과, 선행기술 검색식, 청구항 씨앗, 검증 계획.

### S06 평가 대시보드

Direct/List/VS 비교, 다양성·품질·비용·지연.

## 7. 제외 범위

- 자동 특허 등록 가능성 판정
- 변리사 법률 의견 대체
- 선행기술 전수 조사 보장
- 모델 추정 확률의 통계적 정확성 보장
