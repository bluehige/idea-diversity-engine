# 06. 기존 앱 개선 명세

검토 대상:

- `novel-idea-app.html`
- `ask-authors.html`
- `캐릭터앱.txt`의 기획 원칙

## 1. 현재 구현에서 유지할 점

- 장르·제목·세계관·캐릭터가 이어지는 워크플로
- 반클리셰/참신함 다이얼
- JSON 기반 구조화 응답
- 후보 카드와 전형성 색상 배지
- 작가·관점별 조언을 분리한 에이전트 UI
- 프로젝트 ZIP 내보내기

## 2. P0 수정 사항

### 2.1 제목 생성

현재 방식:

- 반클리셰 모드에서 “각 제목에 대해 내부적으로 3개 후보를 떠올리고 전형적 후보를 피하라”고 지시
- 실제 출력에는 후보 분포와 전형성 값이 없음

문제:

- 검증할 수 없는 내부 휴리스틱이며, 논문의 distribution-level prompt와 다르다.

수정:

- 제목 10개를 바로 생성하지 말고 5개씩 2배치 생성
- 각 제목에 `typicality_estimate`, `title_structure`, `core_hook`, `semantic_axis` 출력
- 배치 간 의미·문법 중복 제거

### 2.2 세계관 생성

현재 방식:

- 후보 5개의 확률 합계를 정확히 100%로 강제

문제:

- 논문에서 각 확률은 반환 후보 집합 내 점유율이 아니라 전체 가능한 응답 분포 대비 추정치다.
- Tail 후보 5개가 모두 0.10 미만이면 합계가 1이 될 수 없으므로 의미가 충돌한다.

수정:

- 합계 100% 규칙 삭제
- 필드명을 `전형성_추정치`로 변경
- 자동 선택이 필요할 때만 클라이언트에서 후보 집합 내 가중치를 별도 계산

### 2.3 캐릭터 생성

현재 방식:

- 빈 필드를 반클리셰 랜덤으로 채우는 구조는 유용하다.

추가:

- 캐릭터 원형, 욕망, 약점, 행동 시그널을 서로 다른 strata로 취급
- 외형만 다른 캐릭터 중복을 감지
- 한 캐릭터의 설정이 아니라 3개 상이한 “갈등 엔진” 후보를 먼저 제안한 뒤 선택

### 2.4 작가에게 묻다

현재 방식:

- 참신함 다이얼 50/20/10/3%
- 후보 5개와 probability
- `<reasoning>` 태그로 단계별 사고과정을 출력

수정:

- `<reasoning>`을 `<cliche_baseline>`과 `<concise_rationale>`로 교체
- UI 명칭을 `등장 확률`에서 `모델 추정 전형성`으로 교체
- 3% 모드는 빈 결과·무의미 후보가 많을 수 있으므로 자동 완화 로직 추가
- 동일 작가의 후속 생성에 이전 후보 canonical summary를 전달
- 작가 간 결과도 의미 중복을 검사

## 3. P1 기능 추가

### 3.1 후보 포트폴리오 화면

카드 필드:

- 제목
- 한 줄 제안
- Head/Mid/Tail
- 의미 축
- 전형성 추정치
- 품질 점수
- 중복 경고
- 핀/병합/제외

### 3.2 커버리지 맵

가로축: 의미 층  
세로축: Head/Mid/Tail  
셀: 후보 수와 평균 품질

### 3.3 생성 이력 메모리

- local-only 버전: IndexedDB + 로컬 임베딩 또는 서버 임베딩
- 서비스 버전: backend vector store

### 3.4 수리 재생성

전체를 다시 생성하지 않고 실패 후보만 교체한다.

## 4. P2 구조 개편

### 4.1 API 키 보안

현재 HTML은 브라우저에서 Gemini API를 직접 호출하고 키를 localStorage에 저장한다. 개인 로컬 도구에는 사용할 수 있으나 공개 제품에는 부적합하다.

수정:

```text
Browser -> Own Backend -> Model API
```

### 4.2 모델 어댑터

`callLLM()`을 다음 인터페이스로 분리한다.

```ts
interface LLMAdapter {
  generateStructured<T>(request: GenerationRequest, schema: JsonSchema): Promise<T>;
  embed(texts: string[]): Promise<number[][]>;
}
```

### 4.3 프롬프트 버전 관리

프롬프트 문자열을 HTML에서 분리해 `/prompts/*.json`으로 저장하고 `prompt_version`을 결과에 기록한다.

## 5. 회귀 테스트

- 세계관 전형성 합계가 1이 아니어도 유효
- 모든 전형성 값 0~1
- 5개 후보의 핵심 메커니즘 중복 없음
- Tail 실패 시 threshold relaxation
- JSON 누락 필드 자동 수리
- API 오류 시 사용자 입력 보존
- 모바일 카드 오버플로 없음
- 내보내기 후 재불러오기 동일성
